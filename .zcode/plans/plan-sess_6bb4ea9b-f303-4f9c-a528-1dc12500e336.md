## dsh-peekedit 插件实现方案

在 `H:\myproject\DSH插件\dsh-peekedit`(当前空目录)从零构建一个可安装的 DSH 插件:bundle 形式(`dsh.bundle` manifest),基于官方包,注册 3 个模型可见工具 —— `peek` / `peek_edit` / `peek_write`,与官方 dsh-tool-fs 工具(可共存、不重名)。

### 项目结构

```
dsh-peekedit/
├── package.json          # dsh.bundle manifest + 依赖 + prepare 构建脚本(git 安装支持)
├── tsconfig.json         # strict, ES2024
├── tsdown.config.ts      # 构建 → lib/(esm)
├── cordis.patch.yml      # patch 层:insert tool-peekedit 行
├── README.md             # 安装/使用文档
├── LICENSE (MIT) / .gitignore
├── src/
│   ├── index.ts          # 插件入口:name/inject/Config/apply,注册 3 个工具
│   ├── support.ts        # 共享机制:resolveTarget、MutationPolicy(sandbox 策略解析+FS_SANDBOX_DENIED 映射)、statExisting、fs/observed 发射
│   ├── peek.ts           # peek 工具(查看)
│   ├── peek-edit.ts      # peek_edit 工具(str_replace + insert)
│   └── peek-write.ts     # peek_write 工具(create + overwrite)
└── tests/
    ├── peek.spec.ts / peek-edit.spec.ts / peek-write.spec.ts   # 单元测试
    └── integration.spec.ts                                     # 挂载真实运行时集成测试
```

### 工具设计(全部走 `ctx.fs` 服务 + fs/* 事件)

**`peek`** — 查看文件/目录
- 参数:`path`(必填,绝对路径)、`view_range`(可选 `[start, end]` 或 `[start, -1]`,1-based)
- 文件视图:带行号的 `cat -n` 风格输出、总行数提示、view_range 切片、超长截断(`<response clipped>` + grep 提示)
- 目录视图:2 层列表、排除隐藏/node_modules/__pycache__、类型前缀排序
- 结构化输出:`{ path, kind: 'file'|'directory', startLine, endLine, totalLines, truncated, content }`;emit `fs/observed`
- UI 卡片:`generic` + `kind: 'read'` + `locations`

**`peek_edit`** — 修改已有文件
- 参数:`command`(enum: `str_replace` | `insert`)、`path`、`old_str`/`new_str`、`insert_line`
- `str_replace`:唯一字面匹配;0 匹配 → `FS_EDIT_NOT_FOUND`;多匹配 → `FS_AMBIGUOUS_EDIT`(带行号);版本守卫写入(`replaceIfVersion`)
- `insert`:0-based 行号插入,不隐式加尾部换行;保留匹配外 Tab
- 经 `ctx.waterfall('fs/edit-intent')` + sandbox 策略 + emit `fs/observed`
- UI 卡片:`diff`(oldText/newText)

**`peek_write`** — 新建/覆盖文件
- 参数:`command`(enum: `create` | `overwrite`)、`path`、`file_text`
- `create`:文件已存在则拒绝(`createIfAbsent`);`overwrite`:版本守卫覆盖(`replaceIfVersion`)
- 经 `ctx.waterfall('fs/write-intent')` + sandbox 策略 + emit `fs/observed`
- UI 卡片:`diff`(新建时 `oldText: null`)

### 共享机制(沿用官方 str-replace-editor 已验证模式)

- `MutationPolicy`:从 `ctx.fs.sandboxMode` + `ctx.sandboxPolicy` 解析每调用沙箱策略;`FS_SANDBOX_DENIED` 映射为 `[sandbox: mode]` 标记
- 错误用 `FsError` 码(`FS_NOT_FOUND` / `FS_NOT_REGULAR_FILE` 等);绝对路径校验(非绝对路径给出 `Maybe you meant /...` 提示)
- 尊重 `exec.signal`;文件 IO 不设超时(遵循官方设计)
- `Config`(schemastery):`maxOutputChars`(默认 16000,peek 截断上限);工具描述可配置

### 依赖(基于官方包)

- peerDependencies:`@deepseek-ai/cordis`(^4.0.1)、`@deepseek-ai/dsh-fs`、`@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-sandbox`、`@deepseek-ai/dsh-sandbox-policy`(rc 版,以 npm 实际发布版本为准)
- dependencies:`@deepseek-ai/schemastery`
- devDependencies:typescript、tsdown、vitest、@types/node 及 peer 包(测试用)
- **实现前先 `npm view` 核对 rc 版本并安装,以发布版类型为准适配 API**(master 与发布版可能有差异,如 `ctx.fs.editText` 若不在 rc 中,则用 `readText + writeText(replaceIfVersion)` 回退 —— 正是官方插件的写法)

### 测试(vitest,仿官方 tools.spec.ts 模式)

- 单元:view_range 校验、行号/截断、目录过滤排序、唯一匹配/多匹配/零匹配、参数校验
- 集成:挂载 `SystemPrompt + ToolRuntime + AgentRegistry + fs-local(或 SandboxPolicy+fs-sandbox)+ fs-observation-policy + 插件`,通过 `ctx.tools.execute(...)` 验证真实调用:读/替换/插入/新建/覆盖、版本守卫、read-before-edit 策略、sandbox 拒绝映射、schema 注册与 `presentCall` 卡片

### 交付与验证

1. 安装依赖并构建(`tsdown` → `lib/`),vitest 全绿
2. 用 `npx @deepseek-ai/dsh web --patch ./cordis.patch.yml` 或本地 dsh 安装 `dsh plugin --profile web add ./dsh-peekedit` 做冒烟验证(若本机无 dsh,则说明验证命令,由你执行)
3. git init + 初始提交

### 风险与回退

- 发布版 API 与 master 有差异 → 以 npm 包的实际类型为准,回退模式(editText → readText+writeText)已预案
- 若 rc 包缺失某些能力(如 sandbox-policy),对应功能自动降级(策略解析返回 undefined,等价官方裸提供者行为)
